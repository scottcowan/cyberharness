# PRD: Cyberharness Intelligence Pipeline

**Status:** Draft  
**Author:** scottcowan  
**Created:** 2026-07-30  

---

## Problem

The local GPU sits idle ~95% of the time. Useful background work —
content pre-generation, knowledgebase maintenance, market intelligence,
OSINT monitoring — is currently either not happening or handled manually.
There is no system that turns overnight idle cycles into structured
intelligence and actionable briefs.

---

## Goal

Build an always-on background intelligence pipeline that runs on the local
GPU during idle periods, produces a daily brief, and maintains a living
knowledgebase — without interfering with realtime inference requests.

---

## Users

- **Primary:** The machine owner (scottcowan) — receives the daily brief,
  acts on opportunity briefs, reviews project-relevant signals
- **Secondary:** etutor-server — consumes pre-generated content packages,
  updated child profiles, spaced repetition schedules
- **Secondary:** cyberharness router — consumes updated local library indexes
  for improved RAG hit rate

---

## Non-goals

- Real-time alerting (push notifications, SMS) — brief delivery is async
- Replacing human judgement on opportunities — briefs inform, not decide
- Public-facing API — internal system only
- Replacing cloud for complex research — local Llama 3B does triage,
  not deep analysis

---

## Requirements

### P0 — Core pipeline (must have)

**JP-01: Job queue**
- SQLite-backed priority queue: `realtime > high > normal > low`
- Realtime queries always preempt background jobs
- Background jobs yield within 500ms of a realtime request arriving
- Jobs are idempotent — safe to retry on failure
- Queue state survives restarts

**JP-02: GPU scheduler**
- Monitors Ollama for active inference requests
- Pauses background jobs when GPU is serving realtime traffic
- Resumes background jobs when GPU idle >30s
- Never allows background jobs to block model loading

**JP-03: Daily brief generation**
- Runs at 04:00 local time
- Output: markdown file at `~/.cyberharness/briefs/YYYY-MM-DD.md`
- Sections: Urgent, Regulatory watch, Technology signals, Market
  intelligence, Project briefs, Indexed (not urgent)
- Delivered to a known location the user checks (configurable:
  file, Obsidian vault, email, Reticulum LXMF message)
- Brief generated by Llama 3B from structured digest — not raw dumps

**JP-04: Cron definitions**
- systemd timers (not cron) for reliability
- Configurable schedule in `~/.cyberharness/config.toml`
- Default schedule defined in spec below

---

### P1 — Intelligence sources (should have)

**JP-05: Log scanner**
- Ingest: etutor-server logs, cyberharness logs, system journal
- Extract: errors, warnings, anomalies, performance regressions
- Output: structured digest → brief "Log anomalies" section
- Runs: 01:00 daily

**JP-06: RSS/OSINT feed ingestor**
- Configurable feed list in `config/feeds.toml`
- Ingests RSS/Atom feeds via `feedparser`
- Deduplicates by URL + content hash
- Stores raw items in SQLite with timestamp
- Default feeds (see Feed Catalogue below)
- Runs: 01:30 daily + every 6 hours for high-priority feeds

**JP-07: Relevance scorer**
- Scores each ingested item against active project context
- Context derived from: `.planning/` across all repos, open backlog items,
  hardware watchlist, technology stack config
- Scoring: keyword overlap + embedding similarity (nomic-embed-text) +
  entity match + recency weight
- Items above threshold: surfaced in brief
- Items below threshold: indexed silently, searchable via RAG
- Threshold configurable per feed category

**JP-08: Knowledgebase updater**
- Watches configured directories for file changes (Obsidian vault,
  `cyberdeck/library/`, `.planning/` docs)
- Embeds changed files via nomic-embed-text → sqlite-vec
- Detects stale entries (content hash changed)
- Runs: file watcher continuous + full re-index 03:00 weekly

**JP-09: Contradiction detector**
- Cross-references new OSINT items against knowledgebase assertions
- Flags when new information contradicts a stored belief
- Examples: price threshold crossed, product delayed, regulation changed
- Output: "CONTRADICTS KB" flags in brief with specific assertion and source
- Uses embedding similarity + Llama 3B to assess contradiction confidence

**JP-10: eBay / hardware price watcher**
- Polls eBay search URLs for configured hardware items
- Compares against price thresholds defined in comparison doc
- Flags items below floor price in brief "Urgent" section
- Tracks price trends over time (is it going up or down?)
- Configurable watchlist in `config/watchlist.toml`

---

### P2 — Content and project intelligence (nice to have)

**JP-11: etutor content pre-generation**
- For each child: pull interest graph + recent sessions from etutor-server
- Generate 5 likely next topic content packages via Ollama
- Generate spaced repetition review content for next session
- Write to etutor-server device sync queue
- Runs: 02:00 daily

**JP-12: etutor session analysis backlog**
- Process completed sessions not yet analysed (interest graph update,
  reading level reassessment, mastery confidence recalculation)
- Generate parent dashboard summaries
- Detect frustration patterns and sensitive topic flags
- Triggered: session end event → job queue → drains overnight

**JP-13: Opportunity brief generator**
- Scans `.planning/` backlog items across all repos
- Matches overnight OSINT/research findings to open items
- Writes structured opportunity brief for each match
- Format: trigger, why relevant, suggested action, effort estimate
- Output: `~/.cyberharness/briefs/opportunities/YYYY-MM-DD-<slug>.md`

**JP-14: CVE watcher**
- Ingests NVD CVE feed filtered to configured stack
  (FastAPI, SQLAlchemy, Ollama, llama.cpp, Python, Ubuntu)
- Flags critical/high severity CVEs in brief "Urgent" section
- Maps CVE to affected service in current deployment

**JP-15: arXiv / HuggingFace / GitHub scanner**
- arXiv: cs.AI, cs.LG, cs.HC — daily new papers
- HuggingFace: trending models, new model cards
- GitHub trending: filtered by topic tags
- Scores against relevance threshold
- Summarises relevant items via Llama 3B (title + 2-sentence summary)

## Brief Format Specification

```markdown
# Daily Brief — {date} {time}

## Urgent
<!-- P0 items requiring action today. Empty section omitted. -->
- [SECURITY] {CVE or security item}
- [MARKET] {price alert below threshold}
- [REGULATORY] {compliance item affecting live systems}

## Contradictions
<!-- KB assertions overturned by new information -->
- [{source}] {new claim} — CONTRADICTS: {existing KB assertion}
  → Suggested update: {doc or assertion to revise}

## Technology signals
<!-- Relevant model releases, framework updates, research -->
- {item}: {2-sentence summary} — {relevance to active project}

## Market intelligence
<!-- Hardware pricing, cloud pricing, economic signals -->
- {item}

## Regulatory watch
<!-- Privacy, AI regulation, children's data -->
- {item}

## Project briefs
<!-- Overnight work outputs — content packages, opportunity briefs -->
- [{project}] {description} — {action or just FYI}

## Log anomalies
<!-- Errors, warnings, performance regressions from overnight logs -->
- {service}: {anomaly description} — {suggested investigation}

## Indexed today
<!-- Not urgent, but searchable. Counts only. -->
- {N} arXiv papers, {N} GitHub repos, {N} news items, {N} CVEs (low severity)
```

## Technical Architecture

```
cyberharness/
  services/
    intelligence/
      __init__.py
      pipeline.py       # orchestrator — runs nightly pipeline
      scheduler.py      # GPU scheduler, job queue management
      feeds.py          # RSS/OSINT feed ingestor
      scorer.py         # relevance scoring
      extractor.py      # article full-text extraction (trafilatura)
      contradictions.py # cross-reference new items vs KB
      cve_watcher.py    # CVE feed, stack filtering
      price_watcher.py  # eBay + hardware price tracking
      brief_writer.py   # Ollama prompt chain → daily brief
      kb_updater.py     # file watcher + embedding queue
      log_scanner.py    # log ingestion + anomaly extraction
  config/
    feeds.toml          # feed catalogue
    watchlist.toml      # hardware price watchlist
    intelligence.toml   # relevance thresholds, schedule overrides
```

**Dependencies (all already in stack or free):**
- `feedparser` — RSS/Atom ingestion
- `trafilatura` — article full-text extraction
- `httpx` — HTTP client (already in requirements.txt)
- `sqlite-vec` — vector store (already in requirements.txt)
- `watchdog` — file system watcher
- `ollama` Python client — Llama 3B for scoring/summarisation
- `nomic-embed-text` — embeddings (already pulled)

## Success Metrics

- Daily brief delivered by 06:00 every morning
- GPU utilisation during idle periods: target >40% (from ~5%)
- Contradiction detection: at least 1 meaningful KB update per week
- Opportunity briefs: at least 2 actionable briefs per week
- RAG hit rate improvement: >20% reduction in Beyond queries for
  library-answerable questions (measured via cyberharness router logs)
- etutor off-plan response time: <200ms (pre-generated) vs 2-5s (on-demand cloud)

---

## Out of Scope (v1)

- Push notifications / real-time alerts
- Multi-user briefs
- Natural language feed configuration
- Automated KB updates (human reviews contradiction flags before updating)
- Social media monitoring
- Paid data sources
